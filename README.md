# Projection Mapping Playground

ブラウザだけで使う、平面ごとの2.5Dプロジェクションマッピングツール。

- 公開: https://kkodamalab.github.io/projection-mapping-playground/
- ソース: https://github.com/kkodamalab/projection-mapping-playground
- Windows Chrome / Edge、WebGL2、HTTPSが対象。バックエンド・APIキー・アプリのインストールは不要です。

## Windowsで投影する

1. PCとプロジェクターをHDMI接続。Windowsの **Win+P → 拡張** を選択します。
2. 公開URLを開き、PROJECTORの出力解像度を選択します。Windows側のプロジェクター解像度・縦横比も合わせます。
3. **OUTPUTを開く** をクリック。ポップアップが止められたら、このサイトで許可します。
4. 出力ウィンドウをプロジェクター側へ移動し、出力内のボタンまたはダブルクリックで全画面化します。Escで解除できます。CONTROLの全画面ボタンは操作案内を表示します（ブラウザのユーザー操作制約）。
5. TEST PATTERNでGRIDを投影し、設置・ピントを合わせます。
6. 領域を追加し、CONTROLの四隅をドラッグして投影対象の角に合わせます。角をフォーカスして矢印キーで1出力ピクセル、Shift+矢印で10ピクセル調整できます。
7. 領域ごとにエフェクトを選びます。選ぶとTEST PATTERNはNONEに戻ります。
8. OUTPUT ONで投影。BLACKOUTは映像を黒にします。設定は自動保存。SAVEでも明示保存できます。

箱はFRONT / RIGHT / TOPなど、面ごとに独立した四角形として扱います。交差・退化した四角形へのドラッグは拒否します。

## カメラ補助（固定平面限定）

1. カメラとプロジェクターを固定し、対象と基準点を同じ平面に置きます。カメラ解像度を選んで接続します。
2. **基準点投影** で9個の白い点を表示し、カメラで **撮影**。
3. **AUTO DETECT** でOpenCV.jsを初めて読み込み、明るい円形輪郭を検出します。
4. 上段左から右、中段、下段の1〜9の番号を必ず確認。ずれはドラッグで修正。失敗時は **9点を手動指定** で同じ順番でクリックします。
5. **対応点から変換を推定**。9点の最小二乗ホモグラフィとカメラ画像上の再投影RMSを計算。RMS 3px以下で保存できます。品質%はRMSを0〜100に線形表示する目安で、統計的信頼確率ではありません。
6. **対象の四隅を指定 → 補正** を選び、静止画像上の対象の左上・右上・右下・左下をクリック。カメラ座標から出力座標へ変換し、選択した領域に反映します。
7. 実際の投影を目視確認して微調整します。カメラやプロジェクターを動かしたら再キャリブレーションしてください。

AUTO DETECTは対応点検出までを自動化します。誤った面への適用を避けるため、点の確認と対象四隅の指定は人が行います。9点すべてが見える・背景が暗い・カメラがほぼ正立している条件が必要です。鏡像、90度回転、強い透視歪み、レンズ歪み、反射面、非平面、遮蔽では正しく検出できない場合があります。RMSが小さくても誤対応を完全には検出できません。

実機なしでも **合成画像 → AUTO DETECT → 変換推定** で動作を確認できます。合成画像モードはカメラ撮影結果ではありません。

## 機能

- 複数領域（最大32）、名前・可視性・独立ソース、四隅の射影変換、メッシュガイド分割。
- WebGLフラグメントシェーダーで逆ホモグラフィを適用。四角形の台形変形も正しい透視補間です。分割数は編集ガイドの密度であり、変換精度を下げません。
- CHECKERBOARD / GRID / DOT GRID / CROSSHAIR / SOLID WHITE / RGB TEST / NUMBERED POINTS。
- GRID FLOW / COLOR WAVE / PARTICLE / GEOMETRIC / NOISE / IMAGE / VIDEO / CAMERA LIVE。
- 速度、明るさ、スケール、色。色設定は単色系エフェクトに適用します。
- BroadcastChannelで出力同期。利用できない環境ではstorageイベントで設定を同期。
- localStorage設定保存、JSON入出力、IndexedDBメディア保存、UNDO / REDO。
- Three.jsによる壁・立方体・直方体・3面パネルのデモ。3面プリセットに異なる映像を割当。
- 日本語 / 英語UI、操作ツールチップ、FPS・出力解像度・カメラ状態。

## 制約・未対応

- 実プロジェクター・実Webカメラでの検証は未実施。自動テストは実機の光学精度や性能を保証しません。
- 3Dスキャン、レンズ歪み補正、エッジブレンディング、深度・身体追従、複数プロジェクターは対象外。
- デモは出力テクスチャを仮想面へ貼る簡易表示。物理投影の光学シミュレーションではありません。箱・パネルは最初の3可視領域を使用します。
- 動画はミュート・ループ再生。音声出力はありません。ブラウザの動画コーデック対応に依存します。
- CAMERA LIVEのウィンドウ間転送は640×360、最大10fpsのJPEGです。BroadcastChannelが必要で、CONTROLを開いたまま使用します。
- JSONに画像・動画データは含めません。同一ブラウザ・同一オリジンではIndexedDBから復元します。他のPCには素材を別途持っていき、各領域へ再読み込みしてください。
- ブラウザデータ消去で設定とメディアも消えます。JSONをバックアップしてください。自動保存のLOADは最後に自動保存された状態を読み込みます。
- 読み込んだ素材はこのブラウザ内で処理します。アプリ自体の配信にはGitHub Pagesへの通信が必要です。
- 高解像度・領域数増加でGPU負荷が増えます。まず720p〜1080pで確認してください。

## 開発・テスト

Node.js 24を推奨。

```sh
npm ci
npm run dev
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

`npm test`はホモグラフィ、逆変換、退化入力、設定JSON、領域追加削除、合成対応点を検証します。Playwrightは実際のChromium上でウィンドウ同期、ドラッグ、履歴、解像度、再読み込み、全画面、カメラ拒否、OpenCV合成画像検出と補正を検証します。GPU非搭載CIではSwiftShaderを使用します。

GitHub Actionsがmain push時に単体テスト→ビルド→ブラウザテスト→Pages公開を実行します。リポジトリのSettings → Pages → SourceはGitHub Actionsに設定します。Viteの相対baseによりリポジトリ配下で動作します。

## モジュール

`model.ts` 状態・検証・座標変換 / `render.ts` 投影・映像 / `sync.ts` 通信 / `media.ts` 素材保存 / `calibration.ts` 遅延OpenCV・検出 / `demo.ts` 3D表示 / `extensions.ts` 将来の追従・遠隔操作・BPM用インターフェース。

次の段階は、実機で平面精度を測定し、露出調整・識別可能マーカー・レンズ歪み補正を追加することです。その後にメディア転送のWebRTC化、複数出力、追従機能を検討します。
